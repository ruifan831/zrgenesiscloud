# ZRGenesis 官网改版方案：产品展示、福利介绍与好友邀请

日期：2026-11-03。状态：用户已确认视觉和福利置顶顺序；首页、导航/页脚与邀请页已接入 Angular，已通过本地构建及定向测试，尚未部署。

2026-11-03 实施更新：首页顺序以用户最新要求为准，福利首屏 → 应用展厅 → 参与步骤与 FAQ → 公司页脚。首页不再保留原先位于福利前的双手机 hero；产品仍由公共 API 驱动，详情图片按已有接口加载。手机邀请设计接入现有业务状态，未新增独立 `/rewards` 路由或改版产品详情页。验收见 [报告](../qa/website-redesign-2026-11-03.md)。以下早期布局表以本段为准。

2026-11-03 同日更新：用户要求福利区更醒目，增加红包与金钱元素；第二版原型以暖金底、朱红标题及红包/金币/奖券插画落实，手机邀请卡同步。保留每日参与、定期开奖与实际活动规则边界。

查看：[当前设计稿与截图](../../../docs/design/zrgenesiscloud-redesign/2026-11-03/README.md)、[设计方向](../../DESIGN.md)。

本轮用户要求先出方案。使用 ui-ux-pro-max 与 impeccable，依据当前官网、项目代码和实际邀请契约提出设计，不将历史 PRD 的产品名单和实现状态视为当前事实。

## 1. 定位与已确认需求

公司官网以真实 App 产品为主角，帮助访客找到适合自己的应用、了解产品内的福利活动，并顺畅承接好友分享。

- 产品展示：清楚说明每款 App 的用途、真实界面和可用下载渠道。
- 福利介绍：加入广告奖励、幸运抽奖、邀请奖励，活动参与发生在对应 App 内。
- 好友邀请：保留专属邀请落地页及现有打开、下载、网页验证路径。
- 用户本轮已确认：抽奖是“每天可参与，按固定周期开奖”，不是每天开奖。

建议品牌主张：“好用的应用，日常的小惊喜。”

首屏副文案草案：“从安排工作到打理生活，我们认真做好每一款应用。在支持福利活动的 App 中，还可以看广告领收益、参与幸运抽奖、邀请好友获奖励。”正式上线前按已开放产品修正文案。

主操作“探索应用”，次操作“了解福利活动”。首屏提供福利入口，同时尽早展示真实产品。

## 2. 现状与本轮判断

- 2026-11-03 用 Chrome 只读检查官网：目前可见全民万年黄历通、班管家；首页为品牌标题、应用速览和产品画廊，没有福利介绍区。未假设工作区其他产品已经公开上架。
- 当前页面有较多留白，首屏和产品区都主要使用 App 图标；下一版应让真实应用界面承担主要视觉叙事。
- 技术栈为 Angular 17 standalone、SCSS 与现有设计 token，产品来自公共营销 API。沿用现有工程与运营入口。
- 邀请页已有 App 优先入口、可折叠网页手机号验证、桌面二维码及微信提示。改版围绕这些能力提升信息层级。
- 当前工作树已有 `relatedAppIds` 邀请身份映射等修改，比 9 月邀请文档更新。保持现有身份校验，不能按设备类型擅自替换 App ID；本轮未验证该映射或产品级关系是否已部署生产。
- 公共福利文档描述了广告任务、周期奖池、邀请、金币/现金及提现等能力，但不能据此宣称每款 App、每个平台当前均开放全部活动。

## 3. 信息架构

| 页面 | 路径建议 | 目的与主要操作 |
| --- | --- | --- |
| 首页 | `/` | 公司产品总览，进入应用详情或福利介绍 |
| 应用详情 | `/apps/:slug` | 功能、真实截图、适用福利、下载渠道 |
| 福利活动 | `/rewards`，新增 | 解释三类机制，选择支持的 App 查看/参与 |
| 好友邀请 | 保留 `/invite/:slug?app_id=...&code=...` | 接受特定产品的好友邀请，打开或下载 App |
| 联系 | `/contact` | 用户支持与合作联系 |
| 协议 | 保留现有规范 URL | 公司说明和各 App 法律文件 |

顶部导航：“应用”“福利活动”“关于我们”“联系我们”。前两项指向首页应用区和福利页；“关于我们”先用首页简短公司介绍锚点，无需新增空泛长页。隐私与协议留在页脚及相应产品页面。

“邀请有礼”放在福利活动中介绍。需要个人邀请码的邀请页由 App 分享链接进入，导航不提供缺少产品和邀请码的通用“立即邀请”入口。

## 4. 首页内容与布局

| 顺序 | 内容 | 视觉与交互 |
| --- | --- | --- |
| 1 | 品牌主张、两个入口、真实 App 预览 | 左侧短文案，右侧 1–2 张真实功能截图与对应产品名；手机端文案和预览上下排列 |
| 2 | 产品展厅 | 按运营排序，每款一个横向展示段：App 图标、用途一句话、核心场景、界面、详情与下载入口；可使用不同产品底色，避免重复大图标 |
| 3 | 福利活动概览 | 连续的三个图文段，介绍广告奖励、幸运抽奖、邀请奖励；浅暖色背景与产品区区分，导向完整介绍 |
| 4 | 如何开始 | “选择 App → 下载并登录 → 进入福利页”；根据产品实际入口调整，不承诺未登录或未满足条件即可参与 |
| 5 | 常见问题与公司 | 回答活动适用范围、抽奖周期、收益查看、邀请生效条件；公司介绍控制在短段，附支持与合作入口 |
| 6 | 页脚 | 产品、福利、支持、协议及真实公司信息；已有备案配置有真实内容时展示 |

产品较少时不增加搜索和复杂分类。未发布产品由运营明确选择是否展示“即将上线”，不因本地存在代码或图标就出现在公开产品列表。

首页结构示意：

```text
ZRGenesis      应用 / 福利活动 / 关于我们 / 联系我们
品牌主张 + 探索应用 / 了解福利        真实 App 界面
产品展厅：黄历通、班管家及后续已公开产品
福利概览：广告奖励 → 幸运抽奖 → 邀请奖励
如何开始 / 常见问题
简短公司介绍 / 支持、协议和公司信息
```

## 5. 三类福利的内容设计

| 机制 | 推荐标题 | 文案草案 | 需要说明的事实 |
| --- | --- | --- | --- |
| 激励广告 | 看广告，领收益 | 在支持活动的 App 中，自主选择观看激励视频，完成后按活动规则获得奖励。 | 哪些 App 支持、奖励为金币或现金、每日限制与到账条件 |
| 抽奖 | 每日参与，定期开奖 | 每天参与活动、按规则获得抽奖份额，在固定开奖周期查看结果。 | 当期规则、开奖周期、参与方式与领奖期限 |
| 邀请 | 分享好应用，邀请有奖励 | 从 App 分享专属邀请链接，好友满足活动条件后，邀请人按规则获得奖励。 | 绑定与奖励的区别、有效邀请条件；只有确认后才写双方获奖或持续分成 |

福利页按“机制简介 → 参与步骤 → 支持的产品 → 常见问题”组织。顶部直接展示三类活动名称；每个介绍段搭配真实功能局部图或明确标识的流程示意，截图中的演示余额不作为收益承诺。

首版以机制介绍为主，不增加实时奖池、个人余额或滚动中奖榜。活动金额、兑换与提现门槛未核实前不写固定数字；可写“具体奖励与提现条件见对应 App 活动规则”。金币不能直接标成现金，不增加手动兑换操作。

“去参与”先选择支持的产品，再进入该产品的合法打开/下载入口。官网本身不播放激励广告、不抽奖、不操作钱包。

## 6. 邀请落地页

保持专属、简短的移动页面，首屏聚焦当前产品与朋友邀请，不加入全站长导航或其他产品推荐。

内容顺序：产品 Logo 与名称 → 脱敏邀请人 → 当前邀请说明 → 该产品适用的奖励摘要 → “打开 App 并接受邀请” → 平台下载入口 → 可折叠网页验证 → 活动规则与协议。

- 已安装：通过明确的点击尝试打开 App，传入原链接的 App ID 和邀请码；不能把点击按钮呈现为已绑定成功。
- 未安装：展示实际配置的下载渠道，并保留“下载后重新打开此邀请链接”的说明，不承诺安装后自动恢复邀请信息。
- 微信：显示“在浏览器打开”指引，保留网页验证的独立入口。
- 桌面：以二维码为主要接续方式，保留产品与邀请说明。
- 网页验证：手机号、验证码和显式同意协议继续作为独立流程；网页协议失败不阻断已验证的 App 打开入口。
- 无效链接、已有邀请关系、已绑定成功、暂时不可用、没有对应渠道，分别显示真实状态；成功后仍可打开 App。

通用宣传的“邀请有奖励”与个人邀请的“奖励会发给谁、何时符合条件”分开说明。好友并不必然获得新用户现金奖励。

## 7. 视觉方向

场景：用户在明亮环境中用手机，从搜索或朋友分享进入，先确认产品身份，再快速找到下载或接受邀请按钮。因此采用清晰的浅色画布，保留公司已有的蓝色操作语言。

### 7.1 风格候选与推荐

用户追加要求明确设计 style，随后确认采用推荐的「现代极简 + 局部玻璃态」。以下保留候选比较；具体首版版式待审阅。

| 方向 | 明确的风格类型 | 画面特征 | 对本网站的判断 |
| --- | --- | --- | --- |
| 玻璃态 | Glassmorphism | 半透明磨砂表面、背景透出、多层叠放、细边界 | 适合作为局部材质；大面积应用会让产品截图、活动规则与背景争夺注意力，主要内容应保持不透明承载面 |
| 极简产品展厅（推荐） | Modern Minimalism，以 Minimalism & Swiss Style 的层级与网格为基础 | 大标题、清楚的网格、宽松留白、真实产品截图、少量有目的的空间层次 | 最符合公司产品展示与下载场景，可让不同 App 保留品牌差异，并容纳福利介绍 |
| 柔和立体 | Soft UI Evolution | 柔和底色、圆润表面、轻微浮起感、温和层次 | 适合强调亲切与活动氛围；作为全站语言需要重新评估现有仅产品图允许阴影的约定，可作为备选而非当前默认方案 |

推荐体系明确为：**现代极简主义为主风格，局部磨砂玻璃为辅助材质，真实 App 截图为视觉主角。** 参考现有项目的 Apple 产品画廊方向，形成清晰的产品展示，不增加装饰性渐变或默认玻璃卡片。

### 7.2 推荐方向在各页面的使用

- 顶部导航：滚动后可使用高不透明度浅色磨砂底，隔离下方滚动内容；首屏保持干净。玻璃效果有明确的分层作用。
- 首页首屏：大字号左对齐标题，右侧以一张主截图和一张辅助截图形成前后层次，使用现有产品图阴影；不把每张截图包进玻璃卡片。
- 产品展厅：不透明、整洁的产品分区，完整展示截图；用对齐、留白和产品自有色彩建立层次。
- 福利区：浅琥珀色背景，真实福利界面或简洁线性图示，标题和规则保持清晰；不设置默认凹凸按钮或装饰性余额。
- 邀请页：简洁浅色页面，以产品标识、邀请人和实心蓝色主按钮为视觉中心；验证码与规则区域保持不透明。

### 7.3 可执行的视觉规格草案

- 色彩角色：现有品牌蓝 `#0066CC` 为主要动作；近白灰沿用 `--surface-light` / `--surface-parchment`，正文沿用 `#1D1D1F`；福利暖底可从 `#FFF4E4`、深琥珀强调色 `#9A5715` 起稿，实施时转为语义 token 并验证实际搭配。
- 玻璃范围：以导航为主，模糊约 12–16px，浅色底约 88%–94% 不透明度。具体取值以滚动后的可读性为准，缺少滤镜支持时使用不透明底；不将技能示例中的低透明度直接用于正文。
- 形状：沿用现有产品图 18px、卡片 12px 与胶囊按钮的体系；不在全站引入新的凹凸或发光控件。
- 字体与动效沿用下方原则；大标题、图像比例与内容节奏承担设计感。

### 7.4 通用视觉约定

- 风格：产品展厅，克制但有真实产品细节；核心视觉为使用中的界面，不是图标堆叠。
- 色彩：沿用品牌蓝作为链接、主按钮和焦点色；浅灰白作主体、深色字作信息层级；福利区增加少量琥珀色及浅暖色底，避免引入第二套按钮色义。
- 字体：保留现有 SF Pro/system 与中文系统字体回退，重做标题/正文的比例及行宽，不照搬技能输出的英文字体。
- 排版：桌面内容宽度约 1152–1200px；手机从 375px 起单列，主要操作触控区约 44px 以上；产品名称和必要说明允许换行。
- 动效：轻量淡入、按钮状态与图片细微过渡，尊重减少动画偏好；不需要自动轮播、金币雨或不断跳动的金额。
- 素材：现有 App 图标保留，新增经核实的产品截图和福利局部截图；首页截图不能拿设计样例冒充已上线功能。
- 设计沉淀：方案确认后新增项目 `DESIGN.md`，引用现有 token 约定并记录新福利区规则。

技能使用说明：ui-ux-pro-max 的两次产品查询没有命中精确的“多 App 公司展示站”分类，返回通用极简/清晰层级方向，故本方案不是产品匹配结果的直接套用。追加风格检索分别精确命中 `glassmorphism`、`minimalism-and-swiss-style` 和 `soft-ui-evolution`，用于上述候选比较；最终组合、颜色和材质范围是结合本网站的设计判断。保留现有品牌与中文字体，按实际信息架构设计；UX 查询中的标签、提交状态提示用于邀请表单，首次错误命中的标题排版结果没有用于解释渐进展示。

## 8. 数据与实施边界

- 产品内容继续由现有公共营销 API 提供，沿用运营后台，不重新建立前端静态 App 清单。
- 当前 `AppEntry` 有功能文案、截图、下载和关联身份，但没有完整的结构化福利展示契约。正式展示每款 App 的活动标签，需要核对真实服务端开关与可公开规则；无法确定时不展示“已开放”。
- 首版可以先完成共用机制说明与现有产品视觉。产品级活动标识如现有公开数据不足，再单独定义最小公共字段，并同步官网类型、后端 schema 与运营编辑入口；本轮不假设新接口已存在。
- 分享链接中的 slug、app_id、code 以及现有关联 App ID 校验保持兼容。产品级邀请关系与各平台身份配置分工遵循服务端既有契约，本次改视觉不重新定义关系。
- 法律页正文与规范路径继续按应用法律页 SOP 维护，本轮不做营销式改写。
- 本轮只形成官网方案，不改变 App 内界面、奖励结算或班管家四端流程；将来若变更这些共享契约，按四端同步规则扩展范围。

## 9. 交付顺序与验收

1. 本轮：定位、页面结构、核心文案与视觉方向提案。
2. 方向确定后：桌面首页与手机邀请页高保真稿，随后补福利页与产品详情；同时核实逐产品活动能力和截图素材。
3. 实施：先完成首页、福利页、产品详情及邀请页视觉，再接入需要的公开展示字段；检查每个平台的真实下载状态。
4. 验收：375px/390px 手机与桌面布局、键盘与字号缩放、加载/空态/失败、邀请上下文和协议流程、真实 App 唤起/未安装/微信路径、法律页预渲染与站内链接。

评价目标是访客更容易找到合适产品和真实下载入口、看懂三类福利，以及完成有效的邀请接续。下载按钮点击不等于完成安装，App 打开点击不等于接受邀请；后续统计应区分这些事件，不上传手机号或完整邀请码。

本轮已核对线上首页视觉、项目入口、现有页面/模型/邀请服务与福利文档。未发送验证码、接受真实邀请、操作奖励、构建、部署或验证原生唤起。
